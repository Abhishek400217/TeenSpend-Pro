# Contributing to TeenSpend Pro

Thank you for your interest in improving TeenSpend Pro.

## Before making a change

1. Read the project README and understand the area you plan to modify.
2. Check existing issues and pull requests so you do not duplicate ongoing work.
3. Keep changes focused. Avoid mixing unrelated fixes or formatting changes into one contribution.

## Working on a change

1. Create a branch from the latest `main` branch.
2. Use a descriptive branch name, such as `feature/budget-filter` or `fix/login-validation`.
3. Make the smallest complete change that solves the problem.
4. Test the affected frontend or backend flow before opening a pull request.

## Pull requests

When opening a pull request:

- Explain the problem and why the change is needed.
- Summarize the important implementation details.
- List the checks or manual tests you performed.
- Add screenshots for user-interface changes when useful.
- Link the related issue, if one exists.

Keep the pull request focused and be prepared to respond to review feedback.

## Security and configuration

- Never commit passwords, API tokens, database credentials, private keys, or production secrets.
- Keep local environment files out of version control.
- Report suspected security vulnerabilities privately to the repository owner rather than publishing exploit details in an issue.

## Questions and bug reports

For a bug report, include clear reproduction steps, expected behavior, actual behavior, and relevant error messages. Do not include personal financial data or other sensitive information in reports.
